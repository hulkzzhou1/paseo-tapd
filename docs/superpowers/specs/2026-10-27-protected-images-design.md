# 受保护 TAPD 图片

Issue #22。用户反馈内嵌图片依然失败。现场反馈环：原图地址返回 302/HTML；官方图片 API 返回的下载链接首次读取是图片，第二次返回 HTML。尺寸探测与展示重复请求同一链接会失败。官方接口说明： https://open.tapd.cn/document/api-doc/API文档/api_reference/attachment/get_image.html 。

本站 TAPD `/tfl/captures/`、`/tfl/pictures/` 图片按单据实际项目调用配置 API 的 `/files/get_image`；daemon 仅读取一次 API 返回的下载 URL，经图片签名/体积验证后，通过 RPC 返回内嵌数据。界面复用同一图片读取，保留等比展示、说明、原图、加载提示和显式失败重试；重试重新调用图片 API，不缓存已消耗链接。描述和评论均传入实际项目。

只接受已配置项目和受支持的 TAPD 图片路径；配置凭据只发往配置 API。下载 URL 来自受信任 API，而非 RPC 任意 URL，校验 HTTP(S)、无账号密码、不得包含配置 Token；每次重定向重新校验，最多 3 次，不附加 Authorization/Cookie。20 秒下载超时，PNG/JPEG/GIF/BMP 签名，8 MiB 上限，拒绝 HTML、SVG 和超量数据。图片不落盘，客户端只在内存暂存，未使用查询 60 秒后清除。外部普通安全图片保持直接加载，不强制走 TAPD。失败反馈不回显请求、服务端内容或秘密。

这替代先前「全部图片由客户端直接请求、无 daemon 中转」决定：单次读取避免临时链接被组件重复消耗，并复用 daemon 对配置 API 的访问能力。代价是 RPC 传输 base64，设体积上限且不保存媒体。

验证：真实失败链路在修改后可由浏览器解码；本地真实工作台用既有图片只读资源验证受保护描述/评论共用读取、失败重试与原有弹窗流程；API 边界验证实际项目、凭据隔离、单次下载、新链接重试、不安全输入/响应/重定向、体积上限。无真实 TAPD 写入、媒体生成或截图。版本 0.4.28，同步 README、OVERVIEW、清单与版本文件。
