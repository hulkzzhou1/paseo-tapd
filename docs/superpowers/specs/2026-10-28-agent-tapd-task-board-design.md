# Agent TAPD 任务看板重设计

状态：设计规则逐项确认完成，已整理实施规格；尚未开始实现。

实施规格已发布为 [Issue #54](https://github.com/hulkzzhou1/paseo-tapd/issues/54)，标签 ready-for-agent。

## 已确认目标与规则

将当前会话侧栏从单据访问入口重新设计为 Agent 的任务看板，查看当前会话未完成和已完成的 TAPD 单据。

1. **状态来源**：每张任务卡片对应一张实际 TAPD 单据；未完成/已完成按所属项目、单据类型的实际工作流判断。插件不维护独立任务完成、重新打开或退出状态。Agent 回合结束不推断任务完成。
2. **职责归属**：每张单据只有一个主要负责 Agent，其他 Agent 可查看和协助。主要负责 Agent 表示插件内承担关系，不等同于 TAPD 人员处理人。
3. **阶段拆分**：需要多阶段或多个 Agent 独立交付时，使用 TAPD 真实任务或子需求拆分并挂在父需求下，各子单据分别分配 Agent。不得用插件中的虚拟阶段任务代替真实单据。
4. **父子跟踪**：主 Agent 通过父需求查看子单据及负责 Agent 的进度，无需同时绑定每个子单据。子单完成不直接推断父需求完成，遵循 TAPD 工作流。
5. **接收任务**：其他 Agent 发起明确委派，目标 Agent 接手后进入其看板；用户可以直接指派，但不自动启动执行。第一版不为新的委派请求额外建设待接收列表。
6. **完成和返工**：完成或重新打开就是修改 TAPD 实际状态，沿用已有授权、合法状态及读回验证规则。保留阶段结果和验证依据；普通查询或再次提到单据不触发变更。其他 Agent 可反馈结果，不能因此直接完成别人的任务。
7. **退出承担**：退出仅解除该 Agent 的承担关系，不增加插件任务状态，不删除或修改 TAPD 单据，不影响其他单据的承担关系。退出原因与历史记录依照 Q18 保存在插件本机。
8. **历史迁移**：此前已同意已有绑定待确认接手，普通查看记录保留最近查看。待确认接手是承担关系确认，不是第二套工作状态；历史多 Agent 绑定依照 Q13 保留并由用户确认主要负责人。

9. **接手冲突与转交（Q12）**：已有主要负责 Agent 时默认拒绝重复接手并返回负责人。用户明确要求转交，或原负责人主动交接且目标 Agent 接受后，才转移绑定；不自动修改 TAPD 人员处理人或状态。
10. **历史多绑定（Q13）**：保留原记录并标注负责人待确认，由用户选择主要负责 Agent，不按最近活跃者推断。确认前禁止新增重复绑定。
11. **生命周期（Q14）**：关闭、重启后恢复；归档保留；删除会话时清理其看板及承担关系，不修改 TAPD 单据。其他 Agent 查看父需求时，对应子单显示未关联 Agent，不推断已完成。

12. **展示（Q15）**：顶部未完成/已完成及数量，默认未完成；使用紧凑双列卡片，显示标题、TAPD 状态、主要负责 Agent。父需求可展开真实子单据及负责人，点击打开详情。最近查看和历史待确认归属为次级入口，不混入正式任务数量。
13. **工具（Q16）**：支持查询当前看板、接手、退出、转交。查询结果与侧栏一致，包含真实子单据和负责关系；默认操作当前 Agent。可查询指定 Agent 以协作，但查询不授予修改其任务的权限。完成和返工复用现有 TAPD 状态工具，不新建独立任务状态接口。
14. **刷新（Q17）**：打开看板读取最新状态，支持手动刷新；可见时每 30 秒刷新，当前工具修改状态后立即更新。失败保留上次数据并标注过期；从未读取成功或不能判断工作流的单据显示状态待确认，不猜入已完成或未完成。状态待确认是数据质量提示，不是额外业务状态。

15. **操作记录（Q18）**：接手、退出、转交等承担关系操作记录保存在插件本机，包含操作者、时间和原因，不自动发送 TAPD 评论。阶段成果与验收依据需回写时，复用已有评论工具及授权规则。

## 验收边界（Q19，已确认）

- 工具与数据：并发接手同一单据仅一个成功；转交权限、历史多绑定、会话删除正确；真实父子单据及 TAPD 工作流状态准确。
- 用户界面：侧栏与工具结果一致；单双列、子单展开、详情操作、失败提示及刷新正常。
- 恢复与写入安全：重启恢复承担关系；恢复和刷新不重放写入；未授权不修改 TAPD 状态或评论。

## 现状与边界

现有「会话单据」是快捷引用，与 Agent 绑定关系不同。查询、操作和明确链接可收录引用，不能直接据此推断为接手任务。现有实现允许多 Agent 关联，需要在实现唯一承担关系时处理历史数据和并发冲突。目前没有专门的当前会话任务看板查询工具。

## 通用 TAPD 标签工具

用户确认：仅暴露 TAPD 的通用标签操作能力，不在工具中内置 Matt 标签枚举、角色分组、互斥规则或自动流转。Matt 等技能可自行约定标签含义并调用工具。TAPD 工作流仍用于判断单据未完成/已完成，标签用于额外信息；插件不另存标签状态。

能力范围：查询项目标签和单据当前标签、创建项目标签、给指定单据添加或移除标签。添加/移除按增量意图操作并保留无关标签，避免调用方为了修改一个标签重建整套集合。项目标签定义与单据标签关联是不同操作。具体支持的单据类型以官方接口和实际部署核实结果为准，不把需求接口能力直接推广到任务或缺陷。

标签写入沿用现有的实际项目校验、明确操作授权、写后回读及结果未知不自动重试规则；查询或调用某个技能本身不触发标签写入。工具不根据标签推断用户授权，也不以标签代替唯一主要负责 Agent 的绑定校验。若接口仅支持整体集合写入，需核对旧值、合并并说明非原子并发窗口。

官方能力核实：

- [项目标签查询](https://open.tapd.cn/document/api-doc/API%E6%96%87%E6%A1%A3/api_reference/label/query_label.html)：支持按项目查询及分页。
- [创建项目标签](https://open.tapd.cn/document/api-doc/API%E6%96%87%E6%A1%A3/api_reference/label/add_label.html)：创建标签定义。
- [更新需求](https://open.tapd.cn/document/api-doc/API%E6%96%87%E6%A1%A3/api_reference/story/update_story.html)：包含 `label` 参数，多标签以竖线分隔，未知标签可自动创建。任务和缺陷的更新文档也已确认支持 label；移除/清空行为和实际部署权限仍需分别核实。

当前代码支持标签筛选，但无专用标签读写 Agent 工具；已有受控文本字段工具的 key 范围不包含 `label`。

## 实施规格前的技术核实

- 核对当前 SDK 与 TAPD 部署支持的子任务、子需求读取/创建接口，不以设计要求推断接口已经支持。
- 核对项目/类型结束状态判定和重开候选；数据不足时显示状态待确认，不硬编码猜测。
- 确定唯一承担关系的原子持久化方式、授权校验、历史多绑定迁移和委派接受流程，以满足已确认的并发与权限边界。
- 明确操作历史随会话删除的清理范围及其他会话中委派引用的展示，遵循已确认的生命周期规则。

这些是需从代码、SDK 和接口获取的事实，不要求用户猜测。若核实结果使已确认交互不可行，再提出具体取舍。
