# Agent 工具关联的存储

服务端主线 SDK 提供 Agent/工作区创建，但插件设置仅支持读取和订阅，不能通过公开 API 保存旧客户端设置中的关联。

承担关系写入插件自己的 `plugin-data/tapd-workbench/agent-links.json`，按 owning daemon、API/站点、实际 TAPD 项目和单据类型/编号约束唯一负责人，串行原子更新。服务端只读核实并导入旧设置为待确认候选；用户明确选择后才形成正式承担关系。客户端只显示服务端生效结果，不合并旧设置，也不调用内部设置协议。旧设置保留为来源，导入指纹和抑制记录防止退出、转交或删除后的关联复活。

代价是新关联不进入原 Git 配置同步，需备份插件数据目录；旧设置无法凭空恢复新工具关联。派发先创建资源、保存关联，再发送提示词；部分失败保留资源并返回阶段和已有 ID，不自动重试或回滚工作区。普通回合自动回评现已停用；阶段评论由显式工具执行并读取实际 TAPD 项目。

任务看板扩展将确认的承担关系与旧关联区分：新记录保存站点、确认时间、操作者与关系 revision，旧记录缺少确认标记时仅为待确认候选。同一 owning daemon 将目标唯一性校验、派发资源保留与持久提交串行化，键不再包含 Agent；冲突不会启动派发。所有界面和工具入口共用该边界，直接界面指派不发送消息。旧设置不因再次读取或绑定自动转换为已确认负责人，跨独立主机不承诺全局互斥。

历史归属确认将旧工具数组兼容读入版本化 envelope；确认后原候选归档、记录来源与审计，并在同一持久提交中保存按实际单据作用域的导入抑制标记。旧设置仍保留源数据，但客户端只展示服务端生效关联，避免设置重放复活被排除负责人。新的明确接手允许在退出后重新建立承担关系；抑制标记只控制历史导入。原有数组 transaction 接口保留，并完整保留 envelope 中的历史、抑制与交接数据。
